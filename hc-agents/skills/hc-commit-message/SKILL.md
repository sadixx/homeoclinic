# HomeoClinic Commit Message and MR

Mirror of RBKS `commit-message` + `gerrit`.

## Branch

`<task-id>-<short-slug>` e.g. `HC-MVP1-047-phonetic-search`.
Never commit on `main`. Never push to `main`, `release/*` or with `--force`
unless the human explicitly asks for a force push on the feature branch.

## Subject

```
<task-id>: <imperative summary, max 60 chars> [M/N]
```

`[1/1]` for single-repo changes (the normal case). Multi-repo changes use
identical subjects with `[1/2]`, `[2/2]`.

## Body (wrap at 72 columns, URLs exempt)

```
[Problem]
Why this change is needed, in the doctor's terms.

[Solution]
What this change does at a high level and how it fits the design.
Do not narrate the diff.

[Requirements]
<REQ-ID>, <REQ-ID>

[Test]
Exactly what ran: unit tests, build, lint, perf numbers, E2E round summary
paths. Never invent tests. If unsure, ask.

This commit was generated by the hc-code-submitter agent
```

## Pre-commit cleanup

1. `cargo fmt --all`
2. `npm --prefix apps/desktop run format` (if the script exists)
3. Trim trailing whitespace in modified files only.
4. `git diff` to review the cleanup.

Never `--no-verify`. Never disable hooks.

## MR (only when explicitly asked to push)

```
git push -u origin <branch>
glab mr create --source-branch <branch> --target-branch main \
  --title "<subject without [M/N]>" --description-file <worklog-dir>/mr.md --draft
```

`mr.md`: Summary, Requirements covered, Validation (all nine gates with
evidence paths), E2E runs, Assumptions, UNVERIFIED notes (if any).

Updating an existing MR: commit on the same branch and push the same
branch. Do not open a parallel MR.
