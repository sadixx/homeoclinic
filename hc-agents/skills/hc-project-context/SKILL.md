# HomeoClinic Project Context

The hc-* equivalent of the RBKS `abbreviations`, `workspace-location`,
`code-tree-routing` and `device-kind` context. Every hc-* agent reads this.

## Workspace locations

| Name | Default path | Override |
|---|---|---|
| `$HC_ROOT` | `~/Doctor-Clinic` | env `HC_ROOT` |
| `$HC_REPO` (code, git) | `$HC_ROOT/homeoclinic` | env `HC_REPO` |
| Requirements | `$HC_REPO/docs/requirements/` | |
| Design | `$HC_REPO/docs/design/` (+ `diagrams/svg/`) | |
| Task tracker | `$HC_REPO/docs/task-tracker/backlog.txt` (source of truth) | |
| Content sources | `$HC_REPO/content-sources/` (`REGISTRY.md` is authoritative) | |
| Worklog | `$HC_REPO/.worklog/<task-id>/` | |
| E2E artifacts | `$HC_REPO/.worklog/<task-id>/e2e/` | |

`$HC_REPO` is a single git repository (monorepo). There is no multi-repo
`repo` tool here, so `[M/N]` numbering is always `[1/1]` unless a task
explicitly spans a second repository (e.g. the Vendor Licence Tool repo).

Repo docs: `docs/CODE-LAYOUT.md` (layout, authoritative), `docs/rules/`
(coding and review rules), `docs/ui/` (MVP1 screen specs, start with
`00-conventions.md`), `docs/adr/` (decisions).

If `$HC_REPO/Cargo.toml` does not exist yet, the code scaffold is pre-M0.
Only HANDOFF and M0 tasks may create it.

## Tech stack

| Layer | Tech | Lives in |
|---|---|---|
| Desktop UI | React 18 + TypeScript, Vite, inside the Tauri webview | `apps/desktop/src/` |
| Desktop Core | Rust, Tauri 2 backend | `apps/desktop/src-tauri/` + `crates/*` |

| Targets | Windows 10/11 x64 (NSIS/MSI), Linux x64 (AppImage/deb) | |

## Code layout

Resolved in `docs/adr/0001-code-layout.md`. `docs/CODE-LAYOUT.md` is
authoritative and overrides requirements/06 section 1 and design/02
section 3. Always read it before creating or moving files.

Milestones: order and release demos are in `docs/milestones/README.md`
(ADR 0002). Every milestone ends with a working, installable release.

Screens: a UI task must name its spec in `docs/ui/S<NN>-*.md`. A screen
with no spec is still a BLOCKING gap.

## Task ids

`HC-<STAGE>-<NNN>` (e.g. `HC-MVP1-047`), epic `HC-MVP1-E04`, feature
`HC-MVP1-E04-F02`. Milestones: HANDOFF, M0..M10, PILOT. Every TASK line in
`backlog.txt` carries type, priority, estimate, requirement ids and a
"done when" check. The "done when" check is the minimum Definition of Done.

## Non-negotiable product rules

1. MVP1 makes zero network calls of its own. It may only hand `wa.me` /
   `mailto:` links to the OS and optionally fetch a signed static update
   manifest. No listening ports, ever.
2. Patient data never leaves the PC unencrypted. No patient data in logs.
3. Parameterised SQL only. Every write is one use-case command, one
   transaction, one audit row.
4. UI never sees SQL or file paths; it calls typed Tauri commands only.
5. Tauri capability allowlist: no shell, no arbitrary FS.
6. `internal_eval` content (OOREP GPL packs) NEVER ships in a public build.
7. Security must never slow the doctor down, add clicks, need internet, or
   lock out a genuine doctor (SUX-001..012).
8. Money is integer paise. Indian number format in UI and prints.
9. Speed targets (NFR): cold start < 4 s, patient search < 100 ms p95 at 50k
   patients (must pass at 100k), open patient < 300 ms, filter < 500 ms.

## Glossary

| Term | Meaning |
|---|---|
| Rubric | One symptom line in a repertory, with graded remedies |
| Repertorisation | Scoring remedies across chosen rubrics |
| MM | Materia Medica |
| Pack / `.hcpack` | Signed read-only SQLite content bundle |
| Channel | `public` or `internal_eval`; decides which signing key a pack needs |
| `.hclic` | Signed licence file |
| UTR | UPI transaction reference used to verify payment |
| DEK / KEK | Data / key encryption key (SQLCipher + Argon2id) |
| CUT | Code under test |
| DoD | Definition of Done |
| MR | Merge request: a GitHub pull request on `sadixx/homeoclinic` (the hc equivalent of a Gerrit change). Tool: `gh` |
